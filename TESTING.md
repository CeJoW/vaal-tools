# Проверка версии 0.2.5

Экспериментальная интеграция с PF2e Summons Assistant 2.20.2 и TCAL 1.2.0, Foundry 14.368 / PF2e 8.5.1. Автоматические проверки не заменяют проверку в мире.

Включите vaal Tools, PF2e Summons Assistant и все его зависимости. Обновите страницу мастера и игрока. Активный мастер должен находиться на сцене с персонажем и противником.

1. На персонаже должна быть способность с slug `inevitable-return` или исходным UUID PF2e. Название может быть переведено. Игрок должен владеть персонажем.
2. Поместите врага Small/Medium в пределах 30 футов на том же уровне сцены. Отметьте его статусом Dead либо отметьте побеждённым в бою при 0 HP без dying/unconscious. Только снижение HP не является триггером в этой версии — это намеренная защита от нелетального урона.
3. Игрок и мастер получают карточку в чате. «Нет» не расходует реакцию. Предложение истекает при смене хода или через 2 минуты (проверяется при нажатии).
4. «Да» создаёт одного тралла на месте тела, с размером тела и владельцами героя. Тело не удаляется. Данные тралла, оформление и эффект срока жизни берутся из Summons Assistant.
5. Повторное нажатие или второе окно игрока не должны создавать второго тралла. Другой герой тоже не может повторно использовать то же тело.
6. При потраченной реакции новая смерть не вызывает предложения. Начало следующего хода героя восстанавливает реакцию. Endless Return предоставляет отдельную реакцию, расходуемую первой.
7. Alt+R открывает счётчик для выбранного токена или назначенного персонажа. Игрок может отметить обычную реакцию потраченной и восстановить реакции своего персонажа. Для вызова макросом: `game.modules.get('vaal-tools').api.reactions()`.
8. Проверьте отрицательные случаи: Large/Tiny, дистанция больше 30 футов, союзник, отсутствующая способность, бессознательный герой, другой уровень сцены. Ни один не должен дать предложение.
9. Между предложением и нажатием отодвиньте героя, оживите цель либо потратьте реакцию: старое предложение не должно сработать.
10. Отключите зависимость: создание должно завершиться понятной ошибкой, а реакция остаться доступной. В журнале браузера не должно быть необработанных ошибок vaal Tools.

Ограничения: ручные реакции других модулей не отслеживаются автоматически; вне боя восстановление выполняется владельцем персонажа вручную. Условие Concentrate при fascinated обрабатывается консервативно (предложение не выдаётся). После обрыва подключения во время создания не повторяйте операцию без проверки токена и счётчика мастером. Полная интеграционная проверка в живом мире ещё не выполнена.

## Счётчик в чарнике — 0.2.1

В разделе Reactions стандартного листа персонажа показан общий запас 1/1. Кнопки USE тратят этот запас и публикуют способность в чат. Это не отдельное применение frequency=1 к каждой способности: Reactive Strike и Shield Block используют один общий запас. Индивидуальный лимит frequency, если есть, также уменьшается. Только Inevitable Return имеет автоматизацию результата; остальные реакции требуют обычного разрешения броска/эффекта игроком или мастером.

Проверить под игроком и мастером: USE первой реакции изменяет счётчик на 0/1 и блокирует остальные; начало следующего хода возвращает 1/1; одновременное нажатие из двух окон расходует только одну реакцию. Для Inevitable Return требуется актуальное предложение; при нескольких целях выбор выполняется в чате. Значок публикации способности остаётся способом показать описание без расхода реакции.

## 0.2.4 — отмена урона и тело
Новые предложения связываются с сообщением урона PF2e при зафиксированном летальном уроне. Отмена этого сообщения удаляет связанный токен тралла и возвращает прежнюю видимость тела; возврат ресурса выполняется только для той же операции в том же цикле реакции. При ручной отметке смерти без летального урона связь отсутствует. Старые траллы автоматически не связываются. Проверить два разных трупа, отмену после нового хода, повторную отмену, скрытое до реакции тело. После успешного создания тело скрывается, но не удаляется. Живая проверка сценария ещё требуется.


## 0.2.5 — ручное восстановление
Владелец персонажа может восстановить общий запас реакций кнопкой ↺ возле счётчика или через Alt+R. Запрос проверяется активным мастером по правам OWNER. Восстановление отменяет старые предложения, но не удаляет траллов и не возвращает личные лимиты frequency отдельных способностей. Проверить восстановление с 0/1 под игроком; попытки изменения чужого персонажа отклоняются.
